# 反馈与推荐机制

## 基础分是规则匹配

程序在题名和摘要中匹配规范化后的词表，不调用大模型或嵌入模型。各项权重：

| 项 | 满分 | 当前实现含义 |
|---|---:|---|
| 主题 | 40 | 研究关键词覆盖比例 |
| 方法 | 25 | 方法词覆盖比例；没有方法词时采用基线适配值 |
| 阶段 | 15 | 综述／方法／研究文章与当前阶段的规则适配 |
| 可用性 | 10 | 有方法词命中时提高规则值，不判断真实复现成本 |
| 互补性 | 5 | 第一版使用固定基线值，不作语义聚类 |
| 依据 | 5 | 是否具有摘要及 DOI／arXiv 标识 |

总分是可解释筛选工具，不能解释为文献质量概率或预测科研产出。文章类型由来源类型或题名启发式识别，误判时应结合原文自行核对。

正常推荐要求摘要、主题覆盖、基础分及排除条件通过。探索项门槛略宽，但同样需要摘要、方法关联和合格基础分，且在总预算内最多保留一个。没有合格探索文章时不会凑数。

当前门槛：正常候选主题覆盖至少 0.4，基础分至少 65；探索候选主题覆盖至少 0.25、方法覆盖至少 0.7、基础分至少 55。命中排除词或未来日期均不入选。仅元数据的文献可以留在候选文件中核对，不作为具有摘要依据的正式推荐。

多个活跃方向按优先级和方向 ID 排列，按轮转方式分配名额。这里的“优先级”只决定取出顺序，不是严格的每方向固定配额。每方向取出时按阶段采用以下文章类型优先序列：

| 阶段 | 前9项的类型优先顺序 |
|---|---|
| `survey` | 4综述 → 3研究 → 2方法 |
| `gap` | 2综述 → 5研究 → 2方法 |
| `focus` | 6研究 → 2方法 → 1综述 |

这是优先顺序而非强行补齐配额。某类没有合格候选时，改选当前方向最高分合格文章；多个方向共用预算时，每方向可能仅得到序列的一部分。有合格探索候选则在总预算内留一个位置，否则不凑探索项。

有效偏好还会调整下一轮检索：保留第一个核心关键词作为方向锚点，其余研究词和方法词按反馈修正排序，让检索模板优先使用更有帮助的词。原始方向配置保持不变，周报保存实际检索词次序。负反馈降低对应优先级和排序分，只有本人显式排除词才直接禁止。

全系统同周最多配置上限个推荐项（默认10），包括同一论文在两个方向分别推荐的两项。调整总预算为较小数值时也不会通过补充文献突破预算。

## 评分与阅读状态分开

1–5 分表示文章对这个方向的价值。阅读状态只表示 `unread` / `skimmed` / `read` / `cited`。已读 1 分依旧是低相关性，未读 5 分仍然可以表达高度预期价值。

空评分不是 0 分，不是负反馈；CLI 用 `--rating none` 撤回评分。相同论文、方向和 profile 版本的最新有效反馈进入计算。同一输入重复保存不累加贡献；改分保留新事件并让旧贡献退出当前状态。

仅有备注不会自动推断正负倾向。理由选择与星级应保持一致：例如“主题不符＋5 分”表达不一致，程序仍会以评分数值为方向，因此保存前应核对。

## 理由代码

| 页面含义 | CLI 代码 | 是否可参与标签偏好 |
|---|---|---|
| 相关 | `relevant` | 是 |
| 方法有用 | `method_useful` | 是 |
| 机制相关 | `mechanism_relevant` | 是 |
| 可复现 | `reproducible` | 是 |
| 问题相关 | `question_relevant` | 是 |
| 主题不符 | `topic_mismatch` | 是 |
| 尺度不符 | `scale_mismatch` | 是 |
| 方法不符 | `method_mismatch` | 是 |
| 内容重复 | `duplicate` | 是，按评分与明确标签归因 |
| 阶段不合 | `stage_mismatch` | 否 |
| 太难 | `too_difficult` | 否 |
| 没时间 | `no_time` | 否 |
| 全文不可得 | `no_fulltext` | 否 |
| 证据不足 | `evidence_insufficient` | 否 |
| 其他 | `other` | 否 |

只有同时提供评分、偏好理由与当前方向中存在的关键词／方法标签，才能归因到标签。未选标签不会从题名擅自推断。“太难／没时间／全文不可得”会保存在记录中，当前版本不会因这些原因降低主题兴趣，也不会自动安排新的阅读计划。

## 小幅迭代

至少累计 3 篇有评分的有效反馈，同一标签至少有 2 条明确归因后才修正该标签。多个标签平分一条反馈的贡献，降低宽泛多标签操作的影响。

评分映射为 1→−1、2→−0.5、3→0、4→0.5、5→1；加上收缩项得到受限目标修正。单标签修正在 −8 至 +8 分内，相关性评分或理由／标签发生变化时一次更新最多移动 2 分。仅修改备注或阅读状态不触发兴趣更新；相同兴趣反馈集合不重复更新，所以反复点击“运行”不会把同一个偏好继续推向上限。

最终修正取论文匹配标签的平均值，加到基础分，保留 0–100 范围。每轮快照保存方向、反馈集合与策略，报告记录有效评分数量与标签修正，方便核对“为什么下周排序变化”。

演示论文的反馈只用于演示模式。真实论文偏好与 demo 偏好分开；不能用合成 5 分反馈训练实际主题。

## 方向版本

修改研究问题、关键词、方法词、排除词或研究阶段时，界面提升 profile 版本。仅改显示名称或启用状态不改变科研问题版本。反馈按版本隔离；旧版本不会自动训练新版本，需要你判断原评价是否仍成立。

版本隔离可避免把“旧模型不需要的尺度”直接排除在新的研究问题之外。文章元数据和历史反馈仍保留，不因版本提升被删除。在历史批次卡片中修改评分时，反馈仍保存在该批次的旧 profile 版本，不会自动迁移到当前版本。CLI 中可以用 `feedback --profile-version 1` 指定实际历史版本；标签也必须来自该历史版本的词表。

## 研究问题和证据

报告列出的待核对问题来自 `questions`。其摘要线索只是帮助定位阅读对象，第一版没有语义判断某篇论文是否回答了某个问题，也没有系统审查反例和全文条件。因此“有若干摘要线索”不等于“已经证实问题未解决”。

确认 gap 或新颖性需要另外开展系统检索、版本核对、全文阅读和逐项证据比较。把已核实的条件写回问题配置，比让系统泛泛生成“未来研究方向”更可靠。
