# 反馈与推荐机制（v2.1.1）

## 从检索到推荐

程序以研究方向为单位运行：核心概念与替代表达生成检索组合 → Crossref/OpenAlex/arXiv 返回元数据 → DOI/arXiv及保守题名／作者规则去重 → 可选 Elsevier 官方接口补摘要 → 概念分类和规则评分 → 可选本地语义排序 → 按该方向剩余周配额选择并保存快照。

每方向每页候选抓取目标默认200，可单独调整到最多1000，与周配额无关。每个检索组合保留全部核心概念；最多6个组合，轮换部分替代表达，方法或综述偏好只追加，不替换核心问题。不同来源对文本查询的语义不同，不能把 Crossref 排序搜索视为严格 Boolean AND；概念覆盖还会在返回后重新核对。

“继续检索下一页”保存新的真实预览批次，沿用父批次的词组、来源和候选抓取量。Crossref使用offset、OpenAlex使用page、arXiv使用start；基本分页受来源限制，不能保证穷尽文献。每一页独立保存，不自动累积合成正式推荐。

## 核心概念与候选分类

`core_concepts` 中每一组表示一个核心概念，组内表达是可替代的匹配入口，组与组是核心推荐必须覆盖的要求。第一个组应填写研究对象，后面的组填写问题或机制。替代表达表示检索扩展，不宣称不同术语在科学定义上完全等同。

旧配置未填写组时，按原主题词保守生成概念组：包含在更长短语中的词不额外增加要求；旧 `dislocation` 加 `mobility` 合成位错迁移率组。少量已编写的相关表达族帮助 HEA、位错迁移率、Peierls–Nabarro 变体检索，其他领域仍需使用者明确配置，不能自动猜测所有同义词。

| 分类 | 条件与用途 |
|---|---|
| 核心候选 | 有摘要、覆盖全部核心概念、最终匹配分至少65，且未命中排除词或未来日期 |
| 探索候选 | 有摘要、至少两个概念组、命中第一个研究对象组且有问题关联线索、组覆盖至少0.5、最终分至少50，但未满足核心条件 |
| 仅标题，待核验 | 没有摘要且没有排除词／未来日期硬排除；保留题名、来源、缺失概念等信息，供人工检查 |
| 被筛除 | 排除词、未来日期或不符合核心／探索条件；保留逐篇原因 |

问题关联线索是词面启发式：后续问题组已有命中，或问题组中有足够具体的部分词命中；方法词本身不能把一般 HEA 腐蚀论文变成位错迁移率探索文献。它仍不是完整语义理解，使用者应核对摘要。

正式批次另外排除在同方向已正式推荐的论文。预览允许重新显示这些论文，并标记历史推荐。缺摘要候选不会自动占周配额；导入 PDF 并人工确认摘要后可重新预览，历史快照不会被重写。

## 基础分与最终分

普通模式在题名和摘要中匹配规范化词组，支持保守的英文复数变体。基础分：

```text
基础分 = 70×核心概念组覆盖 + 10×方法偏好覆盖
       + 15×阶段适配 + 5×摘要与标识依据
最终分 = 限制到0～100（基础分 + 反馈修正 + 可选语义修正）
```

| 项 | 满分 | 实际实现 |
|---|---:|---|
| 核心概念 | 70 | 命中的概念组数／总组数；组内命中任一表达即可 |
| 方法偏好 | 10 | 命中的方法词数，相对最多两个偏好命中归一化；未配置或未命中为0，不作为单独排除条件 |
| 阶段 | 15 | 综述／方法／研究文章与用户所选阶段的规则适配 |
| 依据 | 5 | 摘要及DOI/arXiv标识齐全为1；只有摘要为0.7；没有摘要为0.2 |

旧版固定“可用性”和“互补性”不再提供基础分。选择清单时，用题名词与匹配标签的Jaccard重合度计算实际词面多样性，至多5分作为选取时的排序加分，记录 `selection_novelty`；它不增加卡片显示分，也不是科研新颖性评价。文章类型仍由来源或题名启发式识别，可能误判。

核心／探索门槛使用反馈和可选语义修正后的最终分，不再只检查基础分。但分数不能替代核心概念覆盖、摘要或硬排除条件。每方向在剩余预算内选取；有合格探索项且预算大于1时，最多留一个探索位置，没有时不凑数。阶段通过适配分影响排序，不再强行按旧“4综述／3研究／2方法”等序列选取。

分数是配置匹配工具，不能解释为文献质量概率、正确性或预计科研产出。

## 可选本地语义增强

默认关闭。Sentence Transformers 使用本机CPU上的固定版本 `multilingual-e5-small`，把研究问题和核心概念作为query，题名与摘要作为passage。相似度不是相关概率；长输入最多512个token，全文不在此功能的分析范围内。

程序在有摘要且没有排除词／未来日期硬排除的候选之间，把相似度转为批内相对排序，再计算受限修正；仅标题和硬排除文献不参与百分位计算，也不给语义修正：

```text
语义修正 = （批内相似度百分位 − 0.5）×80×语义权重
```

默认权重0.25，修正范围最多±10分；权重允许0～0.5。批次候选不同，百分位和修正也可能变化。模型不能创造未命中的核心概念或把缺摘要文献提升为正式推荐。

至少3篇有效兴趣反馈，其中至少2篇有摘要的4～5星论文时，把这些论文的平均向量以20%比例混入原问题向量。自由备注、没时间、仅访问困难的反馈不会被编码；模型参数不会被微调。向量缓存按模型版本与文本保存，本地文件加载失败会回退普通模式并显示警告。详见[本地语义增强](本地语义增强.md)。

每方向同周最多推荐配置上限项（默认各10篇）；同一论文分别推荐到两个方向，各占该方向一项。降低上限不会删除历史；已用完配额的方向停止新增，其他方向仍可推荐。候选筛除、预览、PDF获取与摘要确认不占正式配额。

## 评分与阅读状态分开

1–5 分表示文章对这个方向的价值。阅读状态只表示 `unread` / `skimmed` / `read` / `cited`。已读 1 分依旧是低相关性，未读 5 分仍然可以表达高度预期价值。

空评分不是 0 分，不是负反馈；CLI 用 `--rating none` 撤回评分。相同论文、方向和 profile 版本的最新有效反馈进入计算。同一输入重复保存不累加贡献；改分保留新事件并让旧贡献退出当前状态。

仅有备注不会自动推断正负倾向。理由选择与星级应保持一致：例如“主题不符＋5 分”表达不一致，程序仍会以评分数值为方向，因此保存前应核对。

## 理由代码

| 页面含义 | CLI 代码 | 是否可参与标签偏好 |
|---|---|---|
| 相关 | `relevant` | 是 |
| 方法有用 | `method_useful` | 是 |
| 机制相关 | `mechanism_relevant` | 是 |
| 可复现 | `reproducible` | 是 |
| 问题相关 | `question_relevant` | 是 |
| 主题不符 | `topic_mismatch` | 是 |
| 尺度不符 | `scale_mismatch` | 是 |
| 方法不符 | `method_mismatch` | 是 |
| 内容重复 | `duplicate` | 是，按评分与明确标签归因 |
| 阶段不合 | `stage_mismatch` | 否 |
| 太难 | `too_difficult` | 否 |
| 没时间 | `no_time` | 否 |
| 全文不可得 | `no_fulltext` | 否 |
| 证据不足 | `evidence_insufficient` | 否 |
| 其他 | `other` | 否 |

只有同时提供评分、偏好理由与当前方向中存在的关键词／方法／核心表达标签，才能归因到标签。未选标签不会从题名擅自推断。“太难／没时间／全文不可得”会保存在记录中，当前版本不会因这些原因降低主题兴趣，也不会自动安排新的阅读计划。

## 小幅迭代

至少累计 3 篇有评分的有效反馈，同一标签至少有 2 条明确归因后才修正该标签。多个标签平分一条反馈的贡献，降低宽泛多标签操作的影响。

评分映射为 1→−1、2→−0.5、3→0、4→0.5、5→1；加上收缩项得到受限目标修正。单标签修正在 −8 至 +8 分内，相关性评分或理由／标签发生变化时一次更新最多移动 2 分。仅修改备注或阅读状态不触发兴趣更新；相同兴趣反馈集合不重复更新，所以反复点击“运行”不会把同一个偏好继续推向上限。

最终修正取论文匹配标签的平均值，加到基础分，保留 0–100 范围。每轮快照保存方向、反馈集合与策略，报告记录有效评分数量与标签修正，方便核对“为什么下周排序变化”。

演示论文的反馈只用于演示模式。真实论文偏好与 demo 偏好分开；不能用合成 5 分反馈训练实际主题。

## 方向版本

修改研究问题、核心概念、关键词、方法词、排除词或研究阶段时，界面提升 profile 版本。仅改显示名称或启用状态不改变科研问题版本。反馈按版本隔离；旧版本不会自动训练新版本，需要你判断原评价是否仍成立。

版本隔离可避免把“旧模型不需要的尺度”直接排除在新的研究问题之外。文章元数据和历史反馈仍保留，不因版本提升被删除。在历史批次卡片中修改评分时，反馈仍保存在该批次的旧 profile 版本，不会自动迁移到当前版本。CLI 中可以用 `feedback --profile-version 1` 指定实际历史版本；标签也必须来自该历史版本的词表。

## 研究问题和证据

报告列出的待核对问题来自 `questions`。其摘要线索和可选语义相似度帮助定位阅读对象，但程序没有逐项证明某篇论文回答了哪个问题，也没有系统审查反例和全文条件。因此“有若干摘要线索”不等于“已经证实问题未解决”。

确认 gap 或新颖性需要另外开展系统检索、版本核对、全文阅读和逐项证据比较。把已核实的条件写回问题配置，比让系统泛泛生成“未来研究方向”更可靠。
