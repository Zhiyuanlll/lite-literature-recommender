# 自动运行与故障恢复

## 内置周调度

配置位于 workspace 的 `settings.json`，默认关闭。开启后，本地服务每分钟检查设置的星期和时间。时区默认 `Asia/Shanghai`；Python 缺少 IANA 时区库时，内置支持 Asia/Shanghai 和 UTC，其他时区会明确报错。

到期批次 ID 为该周的 `YYYY-Www-real`。同一 ID 的已完成或部分完成批次直接返回现有结果，不重新推荐。配额按配置时区的 ISO 周逐方向汇总，每方向默认各 10 篇。

服务恢复时可以补跑本周已到期但尚未运行的一次任务，不补发上周任务。例如周一 09:00 到期，周二才打开服务，会检查本周该批次；周一 08:00 第一次打开不会补发前一周周一的任务。开启开关时也可能立即补跑本周已到期任务，先检查方向、关键词和预算。

`failed` 批次自动重试的间隔至少15分钟，含首次至多3次执行；达到上限后查看来源警告、处理原因，再用同一 run ID 手动重试。`partial` 代表结果可用但存在警告；相同 run ID 保留原结果，需要额外检索时使用新的 ID并遵守同周剩余预算。

仅启动一次服务，不要同时用内置调度、另一套每周 CLI timer 和 Codex 自动化管理同一 workspace。手动与调度共用锁，另一批推荐正在运行时会明确拒绝重入。

## Linux 登录自启服务

可选脚本建立当前用户的 systemd 服务，作用是启动本地服务，周计划仍由网页设置。默认预览，不安装：

```bash
python3 scripts/install_systemd_user.py --workspace '/自己的workspace' --print
```

确认代码目录和数据目录长期保留后安装：

```bash
python3 scripts/install_systemd_user.py --workspace '/自己的workspace' --install
systemctl --user status lite-recommender.service
journalctl --user -u lite-recommender.service -n 80
```

脚本初始化空 workspace 后再启动服务；不会加载样例或开启周调度。如果发现已有不同内容的同名 unit，脚本停止，要求先检查已有配置，避免无意覆盖。

```bash
# 临时停止／启动，不删除配置
systemctl --user stop lite-recommender.service
systemctl --user start lite-recommender.service

# 取消登录自启并删除本工具的用户 unit
python3 scripts/install_systemd_user.py --remove
```

用户服务的生命周期取决于发行版用户管理器与登录会话。退出登录后仍要常驻，可能需要管理员配置 lingering；本脚本不自动变更该系统设置。电脑关机或休眠时仍无法检索。服务命令的引号、变量和 specifier 处理可参阅 [systemd 官方 service 文档](https://github.com/systemd/systemd/blob/main/man/systemd.service.xml)。

Linux 注册脚本可在目标机器先预览并核对。发行验证可以检查 unit 内容；不等于已经在所有 Linux 发行版上实际安装运行。

## Windows 登录自启任务

在 PowerShell 从项目目录执行，先预览：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_windows_task.ps1 -Workspace 'D:\Research\Literature'
```

确认后添加 `-Install`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_windows_task.ps1 -Workspace 'D:\Research\Literature' -Install
```

脚本为当前用户创建登录触发任务，权限为普通交互用户，使用实际 Python 路径并保留工作目录。不会安装 Windows 服务，也不会开启内置周计划。若 Python 命令无法解析，可增加 `-Python 'C:\实际路径\python.exe'`。

任务名称为 `Lite Recommender Local Service`，可在任务计划程序中查看运行状态。脚本使用单实例策略，并设置持续运行时限；其参数说明见 [Microsoft ScheduledTasks 文档](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset)。取消：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install_windows_task.ps1 -Remove
```

Windows 脚本需在 Windows 上实际验证。Linux 环境的 Python 测试通过不能证明 Task Scheduler 注册与浏览器启动已通过。

## 排错

| 现象 | 处理 |
|---|---|
| `No module named lite_recommender` | 进入解压后的代码目录，或使用启动脚本；workspace 与代码目录不同 |
| Python 版本过低／未找到 | 安装 3.10+，重新打开终端；Windows 可使用 `py -3` |
| 浏览器打不开 | 确认终端服务还在运行，手动打开 127.0.0.1:8765 |
| 端口已占用 | 停止已有服务，或换 `--port 8766`；不要误停无关程序 |
| 未找到活跃方向 | 普通 init 为空；创建并启用方向。demo 可指定未启用示例 |
| 有候选但 0 篇推荐 | 检查摘要是否存在、匹配词、排除词、基础门槛、同周剩余预算 |
| HTTP 403/429 或来源失败 | 查看警告，稍后重试；可先选择其他来源，不把失败当无文献 |
| 缓存回退警告 | 使用了旧缓存，不能据此保证本周新文完整；网络恢复后复查 |
| 标签不能保存 | 只使用当前 profile 的 keywords/method_terms，并检查配置版本 |
| JSON 无法解析 | 备份损坏文件，修复语法或从备份恢复，不用空 JSON 覆盖历史 |
| 周调度没触发 | 检查 enabled、星期、时间、时区、服务日志与同周 run ID |
| “另一个任务正在运行” | 等待它完成；先看日志，锁文件存在本身不代表死锁 |
| 时区不可用 | Windows 可先使用 Asia/Shanghai/UTC；其他时区需系统时区数据 |
| PDF 下载没有文件 | 检查本批次个人星级／cited状态、公开PDF直链及download_report.json；登录页不作为PDF保存 |

OpenAlex API 密钥与 Crossref 礼貌池 email 可选通过环境变量 `OPENALEX_API_KEY` 和 `CROSSREF_MAILTO` 提供。程序不要求将它们写进 profile 或源码；单个服务的访问规则变化可导致来源不可用，检查真实来源警告。

## 备份与恢复

页面或命令 `python -m lite_recommender backup` 生成 `_shared/backups/lite-private-backup-*.zip`。备份使用 SQLite 在线备份接口取得一致数据库副本，同时保存设置、注册表、方向中的 JSON/JSONL/Markdown/TXT 与批次报告；缓存和 PDF 不属于该备份范围。

恢复到新 workspace：

1. 停止当前本地服务或系统启动任务，记录代码版本和备份文件。
2. 保留现有 workspace，把备份解压到一个新的空目录。
3. 确认新目录下直接有 `_shared/library.sqlite`，不是多套一层同名文件夹。
4. 检查 `settings.json`，先令 `schedule.enabled` 为 `false`。
5. 使用 `--workspace '新目录' init` 和 `serve --open` 启动，核对方向、评分和历史批次。
6. 确认后切换启动服务使用的新目录，再重新开启周调度。

SQLite 附属 `-wal/-shm` 文件是运行状态的一部分，不要在服务运行时仅复制主数据库。推荐使用应用备份，或者停止服务后复制整个 workspace。

`python -m lite_recommender verify` 检查软件逻辑，不修复损坏的个人数据库。损坏时先保留原文件，再恢复最近已核对的备份。不要为了“让程序启动”删除反馈历史或把数据库重建成空文件。
