# 从旧 HEA 文献推荐项目迁移

## 先保留原目录

v2 在独立代码目录运行，不改写旧项目源码。原项目和数据先原样备份，迁移完成并核对后再决定是否停止旧任务。不要让旧周任务和新周任务同时管理同一批反馈。

只有旧分享包、没有原电脑的真实数据时，无法恢复历史偏好。新版可以从空状态开始；不要把旧示例评分解释为个人评分。

## 当前迁移范围

导入器读取旧项目的候选论文及 `feedback_history`，从 DOI／arXiv／规范化题名建立稳定身份，再用候选列表映射短编号。直接导入旧累计兴趣权重会继承重复同步等历史误差，因此不导入旧 weights。

来源路径、文件摘要和导入映射保留在迁移报告；重复导入同样记录不重复生成有效贡献。不能确定论文身份、评分或映射的记录进入待核对列表，不猜测邻近文本属于哪篇文章。

迁移不是完整旧工作区同步：当前不自动复制 PDF、不导入 Zotero、不恢复旧下载队列或运行状态，不把旧 Markdown 报告中的任意星号解析成评分。请先检查旧数据文件，再按报告补足未识别的反馈。

## 实际步骤

1. 在原电脑停止旧任务，复制包含真实候选与反馈历史的完整数据目录；保留原目录不动。
2. 在 v2 网页创建目标方向，填写当前问题与词表，例如 `HEA_PN`。避免一个 HEA 总方向吸收所有不同研究问题的反馈。
3. 给 v2 运行一次备份。
4. 在 v2 项目目录执行：

```bash
python3 -m lite_recommender --workspace '/自己的新workspace' \
  import-legacy --path '/旧项目或数据目录' --topic HEA_PN
```

5. 阅读命令输出中的迁移报告路径，核对导入文章数、反馈数和待核对项。
6. 对不确定映射的评分，使用真实 DOI／稳定 paper ID 在页面重新填写。补充当前方向的明确关键词标签；没有标签的旧反馈可能保存了评分，但不影响标签偏好。
7. 重复执行同一导入命令，确认没有重复有效贡献；再试跑新推荐，检查反馈解释与排序。

迁移应从真实逐篇评分重新构建偏好。旧反馈的阅读状态与相关性评分分别保存；“已读”不能代替星级判断。没有可靠映射的记录不会自动变成正反馈。

## 多方向历史怎么处理

一批旧数据若混有 HEA_PN、HEA_mobility 和 DDD 文章，先按研究问题确认归属。`--topic` 表示本次导入的目标方向，不会自动判断每篇文章的用途。可以把同篇论文分别评价在多个方向，但不要把一套主题评分机械复制到所有方向。

## 文件恢复

恢复个人备份前停止 v2 服务，在新目录解压备份并检查顶层 `_shared/`、`settings.json`、`topics.json` 和方向目录。再用 `--workspace` 指向该目录启动。恢复后的第一次启动先关闭自动调度并核对配置，避免迁移旧时间设置后立刻运行。

源码 ZIP 的 `MANIFEST.json` 用于代码校验，不是个人数据备份。源码发布包中不应包含旧数据目录。
