# 完整使用说明

## 1. 安装与启动

要求 Python 3.10 或更新版本。普通模式不需要安装第三方 Python 包，也不要求大模型账号。可选语义增强需安装独立依赖和模型，见[本地语义增强](本地语义增强.md)。

下载源码发行 ZIP，校验后解压到固定位置。程序代码可以放在 U 盘、项目目录或用户文件夹；个人数据可以单独放在另一目录。不要将正在使用的 SQLite 数据库放在多个电脑同时写入的同步目录。

Linux 在项目目录执行：

```bash
bash scripts/run_linux.sh
```

Windows 双击 `scripts/run_windows.cmd`。若窗口马上关闭，在 PowerShell 中执行：

```powershell
cd 'D:\Lite_Recommender_v2.1.1'
scripts\run_windows.cmd
```

macOS 或偏好命令行的用户：

```bash
cd '/自己的解压目录/Lite_Recommender_v2.1.1'
python3 -m lite_recommender init
python3 -m lite_recommender serve --open
```

启动后访问 `http://127.0.0.1:8765`。网页需要本机服务运行；关闭终端后网页中的操作无法继续。端口冲突时增加 `--port 8766`，浏览器地址相应改变。

自定义数据目录：

```bash
bash scripts/run_linux.sh '/自己的研究数据/Literature'
```

```powershell
scripts\run_windows.cmd -Workspace 'D:\Research\Literature' -Port 8765
```

在命令行中指定目录时，全局参数位置是 `python -m lite_recommender --workspace PATH 命令`。双引号或单引号保护包含空格和中文的路径。不要在终端中原样输入 `PATH`、`PAPER_ID` 或 `RUN_ID`；它们是要替换的占位符。

## 2. 创建第一个方向

普通初始化不会替你选择 HEA。打开页面，在方向管理中新增方向，填写大方向、方向 ID、名称、研究问题、核心概念与同义表达、关键词、方法偏好、排除词和研究阶段。

建议按研究问题建小方向：例如“材料”下可建“疲劳裂纹萌生”，“机器人”下可建“触觉操作迁移”。关键词是一条检索词或短语一项，优先填写领域常用英文术语；中文名称适合显示，不应成为唯一检索输入。

核心概念每行一组，组内用 `|` 分隔可替代表达，核心推荐需覆盖每组；方法词只作为加分偏好。旧方向可兼容运行，建议先填清楚研究对象与问题，再做预览。创建后检查启用状态。一次先启用一个方向并试跑，词表稳定后再增加其他方向。每个方向独立计算周配额，默认各10篇；多个方向互不占用。

想学习字段填写，可执行：

```bash
python3 -m lite_recommender init --examples
```

再在网页中选择一个示例、改写问题和词表、启用。四个示例默认关闭。详细字段与分类规则见[方向配置说明](方向配置说明.md)。

## 3. 先做离线演示

在网页中明确选择“离线演示”，或使用：

```bash
python3 -m lite_recommender run --topic medical_imaging --demo --run-id demo-first
```

这会生成带演示标记的合成论文，让你确认推荐列表、星级评分、理由、修改评分和导出流程。演示论文不是真实论文，不用于参考文献，不消耗真实周预算，演示反馈不训练真实推荐偏好。真实检索失败也不会自动转入演示。

演示不是外部 API 健康检查。它的用途是先验证你能完成本地操作。退出演示后再单独运行真实检索。

## 4. 运行真实推荐

检查活跃方向、每方向每周预算和方向关键词，在页面启动真实检索。程序会依次检索公共学术来源，显示候选、来源状态及最终推荐。网络、限流或来源数据格式问题可能使某个来源失败；剩余来源仍可提供候选，结果会记录警告。

每个方向检索的候选数量与最终推荐数量不同。排序前统一论文身份并合并来源，避免 DOI 或预印本版本产生重复。已在同一方向真实推荐的文章通常不会再占用新推荐名额。

查看一张论文卡片时依次确认：

1. 论文题名、作者、发表时间、DOI／原始链接。
2. 依据是“摘要”还是“仅元数据”。
3. 命中了哪些主题词和方法词，评分修正来自何种反馈。
4. 它对应哪一个用户研究问题，有哪些需进一步阅读核对的条件。

只知道年份或月份的论文会保留日期精度，不伪装成近 7 天新论文；未来日期不会作为已发表新文章。报告是阅读入口，不能替代原文阅读或系统综述。

一周的口径由配置时区确定。默认每方向预算 10，可设为任意正整数（包括大于10）。同一方向的手动、定时、多批次共用该方向同周剩余额度；不同方向互不占用；想重现一个批次请复用其 `run-id`，而不是不断创建新批次。合格文章不足时报告会较短。

## 5. 给反馈

个人评分与程序 0–100 推荐分不同。星级表示“对这个方向当前问题的价值”：

| 分数 | 推荐用法 |
|---|---|
| 5 | 直接影响当前工作，优先精读 |
| 4 | 明确有用，值得保存或借鉴 |
| 3 | 部分有用，需要进一步判断 |
| 2 | 与当前问题距离较远 |
| 1 | 明确不适合当前方向 |
| 未评分 | 尚未判断，不作为负反馈 |

阅读状态单独选未读、略读、已读、已引用。即使已经读完但评 1 分，也不会因为“已读”变成正反馈。

再填写具体理由和标签。标签只能选当前方向配置中的关键词／方法词／核心概念表达，页面会显示该论文的匹配词。不要为了保存评分勉强选不对应的标签；不选标签仍会保存评分，但不推断应该强化哪一项研究词。

例子：“方法有用，选 `domain adaptation`，备注‘外部验证设置可作为基线’”比“挺好”更能支持下一轮迭代。“太难”或“没时间”描述阅读安排，不表示该主题不值得推荐。

可以随时改分和撤回。撤回使用页面提供的空评分，或 CLI 的 `--rating none`。最新有效反馈决定当前偏好，历史事件保留审计；重复保存相同反馈不会重复加权。完整理由清单见[反馈机制](反馈与推荐机制.md)。

## 6. 保存和导出

页面提供周报和 BibTeX/JSON/Markdown 导出；CLI 用批次 ID 导出：

```bash
python3 -m lite_recommender export --run-id RUN_ID --format bib --output './weekly.bib'
python3 -m lite_recommender export --run-id RUN_ID --format json --output './weekly.json'
python3 -m lite_recommender export --run-id RUN_ID --format markdown --output './weekly.md'
```

BibTeX 可导入 Zotero、EndNote 等参考文献管理工具。导出保留来源元数据，引用前仍应核对版本、作者、年份和 DOI。演示文件明确标记演示用途。

为实际推荐文章评分后，可选保存评分至少4分或已引用文章的公开 PDF：

```bash
python3 -m lite_recommender download --run-id RUN_ID --min-rating 4
```

读取本批次保留的公开 HTTPS PDF 直链；启用 Elsevier 官方接口且具备相应权限时也尝试授权 PDF，命令行不启用机构浏览器。网页右上角的 PDF 导出会在直链失败后打开专用机构浏览器，运行期间复用登录；机构无法获取时按 DOI 查询 Sci-Hub，无需设置链接。文件放在 `_shared/pdfs/`，已有PDF头有效的文件跳过；无链接或失败会记录独立报告并继续。每文件限制25 MiB，连接／读取超时15秒。下载不改变评分、推荐状态或周预算，也不表示程序已读全文。详见[PDF保存](PDF保存.md)。

点击备份或运行 `python3 -m lite_recommender backup`，记录终端返回的备份路径。推荐后、集中改分后和升级前建议备份。个人备份和源码分享包是两种文件，个人备份不要公开发布。

## 7. 每周自动运行

在页面设置预算和周调度。默认周一 09:00、Asia/Shanghai 时区，调度开关初始关闭。检查电脑的时区库与系统时间；不支持的时区会报错，不能忽略。

服务运行时每分钟检查一次到期任务。仅开网页而没运行 Python 服务、电脑关机或系统休眠都不能执行。关闭服务后也没有后台 Codex 或云任务接管。推荐结果保存在本地页面和报告中，不会自动给他人发邮件或聊天消息。

可以安装登录自启服务，详见[自动运行与恢复](自动运行与恢复.md)。只用这一套周调度，避免同时配置一个额外周任务导致重复触发。

## 8. 移到另一台电脑

在原机做个人备份并停止服务；把源码包和个人备份分别复制到新机。新机安装 Python 3.10+，解压源码，按恢复文档恢复 workspace，然后用 `--workspace` 指向它。不要把运行中的数据库直接同步给正在写入的另一台电脑。

源代码中没有个人偏好；只有源码包而没有个人备份时，新机将从空方向开始。旧 HEA 项目另见[迁移说明](旧项目迁移.md)。

## 验证与局限

```bash
python3 -m lite_recommender verify
```

离线测试使用临时目录与合成元数据，检查身份去重、反馈幂等、改分撤回、方向隔离、预算、日期精度、导出和本地服务边界。它不会修改你的正式反馈，也不证明外部 API 可用。

真实联网验证需要另行启动真实检索，并检查来源警告和论文链接。检索是有限候选召回，不能保证覆盖某领域的全部文献。默认匹配和排序使用概念组及可解释规则；可选本地语义模型辅助排序。词面覆盖、模型的领域适配及过宽排除词仍会影响结果，应通过真实预览与个人评分核对。

当前版本可按用户选择保存公开PDF，不执行全文精读，不自动生成有证据的新颖性结论，不自动推导可信研究空白。它会保留用户问题与摘要层面的证据入口。若需要新增翻译、全文分析或通知渠道，应单独设计其证据、授权和失败处理。

## 真实检索预览与推荐上限

顶部“检索预览”使用 Crossref、OpenAlex、arXiv 中已配置的真实来源，按当前词表和正式相关性门槛筛选。先勾选方向，再预览，调词后再次预览；未启用的方向也可预览。来源有24小时缓存，同词重复预览可能复用结果；修改词表会请求对应的新检索组合。预览也可能返回0篇，不保证达到所设数量。

预览批次保存在历史列表中并标记“检索预览”，可导出。它不占每周配额，不写入正式推送去重记录，不更新反馈策略，不提供评分入口；可以再次显示以前正式推荐过的论文。满意后点击“检索并推荐”，形成正式推荐并评分。正式推荐会排除之前正式推送的论文，因此数量可能少于预览。预览不是自动转为正式批次。

在“设置与定时运行”中修改每个方向每周推荐上限。默认10篇，允许20、30等正整数；个人本地安装各自保存设置。提高上限后本周剩余额度立即增加；降低上限不删除历史推荐，已使用数量达到新上限时停止新增。实际数量受来源候选、摘要、相关性和去重影响，每方向每次最多检索1000个候选。已正式推送后被打低分的论文仍占名额，筛掉的候选和0篇批次不占名额。

命令行（进入代码目录，workspace替换为自己的数据目录）：

```bash
python3 -m lite_recommender --workspace workspace run --topic YOUR_TOPIC --preview --run-id preview-test-1
```

每次新的预览使用新的run-id；相同run-id会重放原批次。


## 下载论文全文PDF

批次右上角“导出”→“下载论文 PDF（ZIP）”。支持真实推荐与真实预览，不要求评分，不占周配额。ZIP含已获取的公开原文PDF及逐篇报告，缺少直链或需登录的论文不会自动下载。详细说明见PDF保存.md。

## 学校访问、官方接口和本地PDF

见[学校访问与PDF导入](学校访问与PDF导入.md)。学校和外部 DOI 入口在设置中配置；本地 PDF 导入及摘要核对入口在真实论文卡片。

## 检索统计、待核验与继续检索

设置中的“每方向每轮候选抓取目标”默认200，最多1000，与本周推荐剩余额度独立。候选是跨来源返回的抓取目标，受重复、来源覆盖、错误或限流影响，去重后可能更少。

在批次中查看“检索与筛选过程”：来源返回、去重、已正式推荐、待核验、核心、探索、筛除和入选数量。展开“候选与逐篇筛选原因”，按分类查看具体文章；未推荐不一定是无关，也可能是已推荐、排序靠后或配额不足。已推荐标记与候选分类可能重叠，不宜把所有统计列简单相加。

无摘要文章在“仅标题，待核验”中保留，不自动占正式周配额。可从候选卡片导入对应 PDF，核对提取摘要后再次预览。摘要确认不会改写旧批次的分类、理由或评分，也不自动推送。

“继续检索下一页（预览）”沿用当前批次记录的检索配置，读取不同来源页码，产生独立预览批次，不消耗正式周配额。中途编辑方向不会改变这一条检索链的查询组合；按新配置重新检索，请使用顶部“检索预览”。每一页不是累计候选池，正式推荐仍需单独运行。

## 可选本地语义增强

普通模式先完成检索和概念筛选，再按配置与反馈排序。需要辅助识别相近表达时，可安装 Sentence Transformers、明确下载模型并在设置启用本地语义增强。无需 ChatGPT 账号或云端 API Key，模型推理在本机 CPU 上执行；缺少模型或依赖时继续使用普通模式。安装、离线使用与限制见[本地语义增强](本地语义增强.md)。
